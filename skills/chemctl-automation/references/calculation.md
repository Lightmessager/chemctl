# 准备计算输入与 PBS 脚本

优先沿用用户现有脚本、方法和环境设置。本文仅给出参数核对与适配原则，不规定默认科研方法。

## 计算定义

- 任务类型：单点能、几何优化、频率、过渡态搜索或已有输出分析。
- 分子坐标、总电荷、多重度，是否需要约束、对称性处理或已有 checkpoint。
- 方法/泛函、色散修正、元素/原子基组分配与 ECP、溶剂模型和名称。
- 引擎版本、队列、核数、内存、最长运行时间、可执行文件绝对路径。

不足以构成可靠输入时只询问缺失信息；不猜电荷、多重度或金属 ECP。用户已有约定和脚本优先，不强制重新批准既定参数。创建/修改化学输入前参考目标引擎版本的官方语法，尤其是混合基组、ECP、溶剂和复合任务。

## Gaussian 混合基组

`GenECP` 或 `Gen Pseudo=Read` 分别包含轨道基组块和 ECP 块。同一元素或编号选择器的轨道基组与 ECP 是两回事。比如用户明确指定 Pt 使用 SDD、C/H/O 使用 6-31G(d) 时，按对应元素构造块；SDD 不能从输出文件名或“重原子”泛称自动推断。输入最后所需空行不能省略。

Gaussian 输出的 `Centers:` 采用 1 起始原子编号。chemctl 会按这些编号关联元素并保留分组；`ecp_centers` 显示解析到的核心电子数。没有命名基组证据时只显示自定义壳层，不反向猜基组名称。

## PBS 执行

使用 Bash/sh 脚本。`#PBS` 中写明资源；不要把含私钥、数据库、其他项目的目录上传。程序在独立任务目录运行脚本，原脚本负责环境与实际计算程序命令。

- ORCA：使用已确认的化学程序绝对路径；输入 `%pal nprocs` 与 PBS 核数一致，`%maxcore` 是每进程内存预算，需要给其余程序留余量。不要对主程序盲目再包 mpirun。
- Gaussian：核对版本相应 profile、可执行文件和 `%nprocshared`、`%mem`；scratch 放本任务独立子目录，避免写到共享目录根。需要长期保存的 checkpoint/输出复制回任务目录。
- 脚本保留真正计算命令的退出码；避免用最后一个成功 echo 掩盖计算失败。重定向输出到 `.out` / `.log`，便于同步解析。
- 后台自动包装退出记录、唯一任务名与 scheduler.stdout/stderr；不要改动 `.chemctl-*` 保留文件。
- 只同步任务目录，写到其他 scratch 的结果不会自动出现。作业失败时先同步并看 stderr/原始输出，再决定是否有依据做一次有界修正；变更科学定义需重新获得该变更的授权。

验收只做用户所需计算。不要为“确认安装”额外运行科学作业，也不要为消除虚频自动无限重算。
